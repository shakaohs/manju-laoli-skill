# 故事连续性引擎（Story Continuity Engine）

> V1.0 · 故事层连续性唯一工作规程。它管理“故事发生了什么、谁知道什么、谁欠谁什么、哪些问题尚未兑现”；不替代 sd-qc-engine 的视觉连续性账本。

## 一、目标与适用范围

本引擎为原创、改编、续写三种模式提供统一的故事状态底座。每次规划、续写、改写、跨批生产前，先读取最近一次锁定状态，再根据本次正式内容生成状态差分。

必须保证：
1. 已发生事件不会被无授权地改写、抹除或重复发生。
2. 人物只使用自己已经获得的信息，不发生“作者知道、角色也知道”的越权。
3. 人物关系、立场、目标、伤势、资源、承诺随事件变化，不在集与集之间无因跳变。
4. 伏笔、疑问、威胁、交易、承诺均可追踪其提出、升级、兑现、转化或撤销。
5. 新内容必须由已知事实、人物行动和可见因果支撑；未知处保留 OPEN_ITEM，不用模型常识补成事实。

## 二、权威顺序与事实标签

冲突时按项目实际模式执行，不得把低权威材料覆盖高权威材料。

- 原创：用户明确要求/裁定 > 已锁定故事圣经 > 已锁定分集规划 > 已确认剧本 > 当前草稿。
- 改编：用户提供的原作事实 > 用户明确授权的改编决策 > 锁定改编蓝图/IP/故事圣经 > 锁定分集规划 > 当前剧本。
- 续写：用户明确续写指令/纠错 > 已确认正典剧本（按集数顺序）> 最新连续性账本 > 已锁定圣经与分集规划 > 未确认草稿/讨论意见。

每条信息必须使用以下一种标签：
- `FACT`：来源文本或已确认剧本明确发生/明确陈述。
- `INFERENCE`：由多个事实推导，但原文未明说；必须写明推导依据。
- `ASSUMPTION`：为了推进创作暂设；不得伪装事实，必要时交用户确认。
- `USER_OVERRIDE`：用户明确推翻此前设定；记录被覆盖项、理由、影响范围和生效版本。
- `OPEN_ITEM`：资料缺失、矛盾或尚未揭晓；禁止擅自补齐。
- `REJECTED`：曾被提出但用户或锁定规则否决的方案；避免后续再次误用。

## 三、故事状态账本

项目级主账本建议命名 `STORY_CONTINUITY_LEDGER.md`，结构化状态建议命名 `STORY_CONTINUITY_STATE.json`。若平台不支持文件系统，可在对话中维护同名逻辑文档；不得谎称已写入磁盘。

### 3.1 必备分区

| 分区 | 记录内容 | 更新触发 |
|---|---|---|
| Canon & Sources | 正典版本、来源范围、事实标签、用户裁定 | 新材料登记/设定变更 |
| Event Ledger | 事件 ID、时间、地点、参与者、起因、行动、结果、证据 | 每场/每集锁定 |
| Character State | 目标、动机、认知、误解、情绪、伤势、资源、秘密、承诺 | 事件改变人物状态 |
| Relationship State | 双方关系、信任、权力、债务、公开/私下立场、变化原因 | 关系发生可见变化 |
| Knowledge & Evidence | 谁知道什么、来源、可信度、谁尚不知道、证据保管人/流转 | 新线索/证词/文件出现 |
| Promise & Debt | 誓言、交易、期限、代价、责任人、履行状态 | 承诺/交易产生或变化 |
| Hook & Mystery | 悬念问题、观众已知/未知、角色已知/未知、责任集、兑现计划 | 钩子提出/升级/兑现 |
| Open Items | 缺失、矛盾、待用户裁定、不可推断项 | 发现未知或冲突 |
| Change Log | 变更前后、触发事件、影响集数、批准者 | 每次状态更新 |

### 3.2 事件记录模板

每个事件使用唯一 ID（如 `EVT-EP012-03`），至少记录：
- `episode / scene / story_time / location`
- `participants` 与各自行动（不能只列在场人物）
- `trigger`：事件为何此刻发生
- `action`：可观察的行为
- `outcome`：局势、资源、关系或认知改变
- `evidence`：观众/人物可以据此判断的事实
- `state_delta`：本事件对人物、关系、证据、承诺、钩子的改变
- `source_tag` 与 `confidence`

没有状态变化的事件应说明其戏剧功能；连续多个场景只重复同一信息时，合并或重构。

### 3.3 人物状态模板

每个主要人物按“目标—动机—认知—策略—代价”维护：
- 当前外部目标 / 深层需求
- 当前动机与压力源
- 已知事实、错误认知、未知信息（分开列）
- 当前策略、备选策略、不能采取的行动及原因
- 情绪与关系立场（由具体事件触发）
- 身体状态、伤势、能力限制
- 可用资源、控制资源、欠下的债
- 已作承诺、期限、履约能力
- 本阶段弧光：旧信念 → 冲击 → 选择 → 代价 → 新状态

人物改变必须有触发事件、主动选择和可见代价。不得只因剧情需要突然变聪明、变蠢、变忠诚或改变称呼/态度。

### 3.4 知识隔离表

线索不等于所有人物都知道。每条线索记录：
- 线索 ID、内容、首次出现集/场；
- 来源人物/物证/文件及可信等级；
- 亲眼所见、听说、推断、误传中的哪一种；
- 当前持有人、已阅读/听闻者、尚未知情者；
- 是否公开、是否被污染/伪造、可否作为定论；
- 观众知道程度与角色知道程度。

角色在获得信息前不得据此行动；角色推断可以出错，但必须符合其已有信息和认知能力。证据转手、遗失、毁损、伪造必须留下事件记录。

## 四、悬念与承诺债务管理

所有需要未来回应的内容进入债务账本，不允许只靠模型“记得”。

每条债务至少有：
- `debt_id`、类型（PROMISE / THREAT / MYSTERY / CLUE / DEAL / CONSEQUENCE）；
- 提出集/场、提出者、承接者、明确内容；
- 当前状态：`OPEN / ESCALATED / PARTIALLY_PAID / PAID / TRANSFORMED / CANCELLED_WITH_REASON`；
- 观众预期、角色预期、最晚回应窗口；
- 计划兑现集/场、兑现方式、所需证据/资源；
- 延迟原因及用户授权（如超出原计划）。

规则：
1. 每集结尾钩子必须进入账本；下一集开场要么立即回应，要么明确推进该问题。
2. “兑现”必须产生可观察结果，不能用另一句更大的疑问替代。
3. 部分兑现要明确剩余债务；转化/取消必须有剧情原因。
4. 不得连续堆叠无兑现的重大承诺；规划时检查债务数量、年龄和集中度。
5. 误导性线索必须最终说明误导机制，不可用“角色误会”无限拖延。

## 五、跨集状态更新协议

每完成一集或一个正式批次，按以下顺序执行：
1. 读取上一版锁定账本及本集来源/分集卡。
2. 提取本集真实发生事件，不从意图或未拍出的计划更新事实。
3. 生成状态差分：新增、变化、结束、仍未知。
4. 对每个变化标注触发事件 ID 和事实标签。
5. 更新人物认知隔离、关系状态、证据流转和债务状态。
6. 对照上一集出口状态与本集入口状态，检查时间、地点、行动、伤势、资源、称呼、关系。
7. 生成下一集入口约束与未偿债务清单。
8. 自检通过后才将账本标记为 `LOCKED`；否则标记 `STALE` 或 `BLOCKED`。

禁止将“下一集计划发生”写进“已经发生”。计划、草稿、用户确认和正式正典必须分栏。

## 六、续写前的强制读取顺序

续写前按顺序读取：
1. 用户本轮续写要求与纠错；
2. 最近连续的已确认剧本（至少上一集完整剧本；跨批时读取上一批末集及必要前情）；
3. 最新 `STORY_CONTINUITY_LEDGER`；
4. 当前人物状态、关系状态、知识隔离表；
5. 未兑现的承诺/钩子/证据链；
6. 锁定故事圣经、分集规划与禁改项；
7. 如为改编，读取对应原作章节与改编追踪表。

若关键前情缺失，先列出缺失项并请求用户补充/确认；不得假装读过未提供的集数。用户只提供某一集时，只能把该集及明确说明的前情作为已知输入。

## 七、冲突检测清单

每次锁稿前逐项核对：
- 时间与年龄：事件顺序、日期、昼夜、人物年龄是否冲突；
- 空间与行动：人物如何抵达、离开、取得/失去物件；
- 认知：角色是否知道尚未获知的事实；
- 动机：行动是否符合当前目标、压力与利益；
- 能力与资源：钱、人手、权限、证据、技能是否凭空出现；
- 关系：信任、称呼、阵营、权力变化是否有触发事件；
- 伤势与代价：受伤、疲劳、损失是否被无故清零；
- 证据链：来源、持有人、真伪、可采信程度是否连续；
- 承诺债务：期限、责任人、兑现/延期/违约是否明确；
- 悬念：提出、升级、部分回应、完整兑现是否可追踪；
- 改编边界：是否把原作未知写成原作事实，是否越过用户授权；
- 正典版本：是否误用未确认草稿或被否决方案。

发现问题先输出 `CONTINUITY_ISSUE`（严重度 P0/P1/P2、涉及集场、证据、影响、修复选项），不得悄悄改写正典。

## 八、交接格式

每集/批次结束时输出：
- `ENTRY_STATE`：本集开场继承的事实与人物状态；
- `EVENT_DELTAS`：本集新增事件及状态变化；
- `CHARACTER_EXIT_STATE`：主要人物出口状态；
- `RELATIONSHIP_DELTAS`：关系变化与触发事件；
- `KNOWLEDGE_DELTA`：谁新知道了什么、谁仍不知道；
- `EVIDENCE_CHAIN`：新增/转移/损毁的证据；
- `OPEN_DEBTS`：未偿承诺、钩子、威胁、谜题；
- `NEXT_ENTRY_CONTRACT`：下一集必须承接的第一动作/第一问题；
- `OPEN_ITEMS`：不能自行补齐的未知项；
- `LOCK_STATUS`：LOCKED / AWAITING_CONFIRMATION / BLOCKED。

## 九、与视觉连续性账本的边界

本账本是“故事层”：人物认知、动机、关系、承诺、证据、因果和悬念。
`sd-qc-engine/references/continuity-ledger.md` 是“视听制作层”：人物外观、服装、道具、场景、站位、镜头、时间轴等。
同一事件 ID 可在两个账本中互相引用；不得将两者合并成一个含义不清的“连续性表”，也不得重复定义对方的权威字段。
