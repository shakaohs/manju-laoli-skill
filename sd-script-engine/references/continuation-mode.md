# 原创 / 改编 / 续写三模式路由

> V1.0 · 本文件定义创作模式识别、模式专属流程与切换门禁。总控负责识别和路由，sd-script-engine 负责执行。

## 一、先识别任务，不混淆素材来源与创作模式

素材来源锁（原创 / 改编 / 对标 / 热点）与创作模式（原创开发 / 原作改编 / 既有项目续写）是两个维度，不可互相替代。

- **原创开发（ORIGINAL）**：用户要求从零构思，或只给题材/一句话方向，没有需要遵守的既有正典故事。
- **原作改编（ADAPTATION）**：存在小说、网文、大纲、剧本、真实事件资料或其他原作，用户要求将其转为剧本/漫剧。必须维护来源追踪和改编授权边界。
- **项目续写（CONTINUATION）**：已有一套已确认的剧本/分集/故事圣经，用户要求从指定集数、场景、批次或断点继续。续写的核心是继承正典，不是重新开发。
- **改编项目续写（ADAPTATION_CONTINUATION）**：同时具备原作改编来源和已确认的改编剧本正典；续写时同时继承改编正典与原作约束。

用户已明确模式时不得重复询问。无法判断时只问一个最关键问题：“这是从零原创、依据原作改编，还是接着已有剧本往下写？”输入材料明显属于某模式时可先识别，但要把不确定项列出，不可擅自锁定。

## 二、模式路由表

| 模式 | 首要权威 | 首轮工作 | 必须产出 | 禁止事项 |
|---|---|---|---|---|
| ORIGINAL | 用户裁定 + 锁定圣经 | 题材承诺、核心命题、人物欲望、主冲突、终局 | 原创故事圣经、全剧弧线、分集规划 | 无因借用现成 IP；未定终局却假装全剧闭环 |
| ADAPTATION | 原作事实 + 用户授权 | 来源登记、原作事实/推断/空白扫描、改编蓝图 | 来源映射、保留/压缩/合并/新增授权表 | 把推断升格事实；未经授权改变核心身份/关系/谜底 |
| CONTINUATION | 已确认剧本正典 + 最新故事账本 | 断点识别、上一集/批次复盘、状态差分 | 续写入口合同、未偿债务、续写分集卡/剧本 | 重启故事、重复介绍、人物失忆、擅自填补缺失集 |
| ADAPTATION_CONTINUATION | 改编正典 + 原作约束 | 双轨核对：改编剧本当前正典 vs 原作后续事实 | 双轨连续性报告、授权范围内续写 | 用原作后文覆盖用户已确认的改编分歧 |

## 三、原创模式工作流

1. 需求拆解：题材、受众、平台、集数范围、单集时长、情绪体验、禁区、交付形态。
2. 核心承诺：一句话 premise、观众追看理由、独特机制、主角不可替代性。
3. 因果发动机：主角目标、阻力系统、对手利益、失败代价、升级机制。
4. 终局设计：主问题答案、人物弧光落点、主要关系结局、主题选择；允许用户选择开放式结局，但必须明确哪些问题有意开放。
5. 故事圣经：世界规则、人物、关系、阵营、资源、秘密、证据机制、时间线。
6. 分集规划：先全剧弧线，再分幕/阶段，再分集卡；最后抽检开头、中段、转折、终局。
7. 正式剧本：按已锁定分集卡生产；每集更新故事连续性账本。

原创仍需标记 ASSUMPTION 与 OPEN_ITEM；“原创”不等于允许逻辑无约束。

## 四、改编模式工作流

1. 登记原作名称/版本/章节范围/用户提供材料范围；建立来源清单。
2. 对原作逐段提取事实、人物、事件、因果、规则、证据、伏笔和结局；记录章节/段落定位。
3. 标出原作空白、矛盾、未揭晓事项；保持 OPEN_ITEM。
4. 形成改编蓝图：保留、压缩、合并、重排、删除、新增连接材料分别列出；每项标注理由、影响和授权状态。
5. 建立“原作事实 → 改编处理 → 剧本落点”追踪表；关键改变需用户授权。
6. 锁定改编圣经与分集规划；写剧本时检查来源覆盖和新增内容边界。
7. 每批剧本完成后更新故事连续性账本和改编追踪表。

改编新增材料分级：
- A类：不改变事实和因果的表演化/场景化连接；
- B类：不改变核心设定的次要补充，需明确标记并在项目规则允许范围内使用；
- C类：改变人物身份、关系、关键证据、胜负、谜底、能力规则或结局，必须用户明确授权。
禁止将 C 类改动包装成“合理补充”。

## 五、续写模式工作流

1. 识别续写断点：最后一集/场/批次、目标起始集、用户指定剧情任务。
2. 建立正典包：已确认剧本、最新故事连续性账本、人物关系/认知状态、证据链、承诺债务、锁定分集卡和禁改项。
3. 输出续写入口合同：已发生事实、当前局势、人物目标、各自认知、未偿债务、不能改变的事实、缺失材料。
4. 做续写可行性判断：信息是否足够；若缺关键集/关键账本，列缺口并请求补充，不能假装已读。
5. 先提出续写方向或按用户要求直接续写；续写方向必须承接现存冲突，不以重复解释代替推进。
6. 规划下一段/下一批：明确本批局部目标、局部兑现、局势变化、长期主线推进和下一批入口。
7. 正式写作：开场承接上一集出口状态；每集推进至少一个真实状态变量；结尾钩子必须进入债务账本。
8. 更新账本：只把已写成并确认的事件记入正典；草稿标记 DRAFT，不得提前锁定。

## 六、续写断点与缺失材料处理

- 连续集数齐全：按顺序读取并生成连续性摘要，不必要求用户重复介绍。
- 缺少中间集：明确列出缺失集数；不得把上一份文件和下一份文件自动视为无缝连续。
- 用户提供“前情梗概”：可作为用户提供的摘要事实，标签 USER_SUPPLIED_SUMMARY；未经原剧本核验的细节不得伪装逐场事实。
- 只有最后一集：可以从该集明确出口状态续写；此前人物/证据/伏笔若未出现则列为 OPEN_ITEM。
- 用户要求跳集/改线：记录 USER_OVERRIDE，标注被跳过内容及对后续的影响。
- 用户纠正：立即更新事实来源和账本版本，检查所有受影响集；不得辩解或悄悄保留旧错误。

## 七、三模式共用的每集生产合同

每集至少回答：
1. 本集主角要什么？阻碍是什么？
2. 主角采取了什么具体行动/策略变化？
3. 对手或环境如何有效反制？
4. 本集结果改变了什么（信息、关系、资源、权力、风险、承诺至少一项）？
5. 本集局部问题如何获得兑现？
6. 下一集问题是什么，为什么必须现在继续？
7. 哪些人物知道了新信息，哪些仍不知道？
8. 本集产生/偿还了哪些承诺与悬念债务？
9. 本集哪些内容来自原作，哪些是授权改编/原创？
10. 本集结束后的状态是否可供下一集直接接续？

## 八、模式切换门禁

模式切换不是简单改标签：
- ORIGINAL → ADAPTATION：新增原作后，重新执行来源登记、事实扫描、改编蓝图与受影响分集审计。
- ORIGINAL → CONTINUATION：用户确认当前剧本为正典后，锁定当前版本与账本，建立续写断点。
- ADAPTATION → CONTINUATION：保留原作来源链，额外锁定改编剧本正典。
- CONTINUATION → REWRITE：必须明确是局部修订、整集重写还是全局改编；检查对后续集数和账本的影响。
- 任何切换都生成变更记录，受影响的下游产物标记 STALE，不能静默沿用。

## 九、最小入口输出

识别后仅展示与任务有关的入口，不重复询问已经明确的信息：
- ORIGINAL：输出原创需求缺口与第一阶段开发目标。
- ADAPTATION：输出待登记的原作范围与来源缺口。
- CONTINUATION：输出已识别的续写断点、已掌握材料和关键缺口。
若用户已给出完整信息且要求直接执行，跳过入口问答，按门禁直接工作。
